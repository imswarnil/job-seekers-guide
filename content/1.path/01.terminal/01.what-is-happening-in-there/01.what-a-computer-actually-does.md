The machine on your desk is about to stop being opaque, and it takes less than you
think: a computer does four things, and it does them stupidly.

## Why this matters in a job

Because every confusing bug you will ever meet comes from the same mismatch. You
meant something. The machine did what you wrote. Those were different, and the
machine has no mechanism for noticing, because it has no idea what you meant.

Developers who think of a computer as clever spend their careers asking "why did
it do that?" Developers who think of it as fast and literal ask "what did I
actually tell it to do?" That is a question with an answer.

## Four verbs, and nothing else

Strip away the screen, the icons and the animations, and a computer takes in
data, holds it somewhere, does arithmetic and comparisons on it, and puts data
back out. That is the entire job.

::flow{numbered caption="Every program you will ever write is these four boxes, in a loop."}
  :::flow-step{label="Input" icon="i-lucide-keyboard"}
  Something arrives: a keystroke, a click, a file being read, a request from
  another machine. An applicant types their marks into a form.
  :::
  :::flow-step{label="Storage" icon="i-lucide-database"}
  It is put somewhere it can be found again: a numbered location in memory. The
  number `87` now lives at an address.
  :::
  :::flow-step{label="Processing" icon="i-lucide-cpu" highlight}
  Arithmetic and comparison. Add these. Is this bigger than that? This is the
  only clever-looking step, and it is neither of those words.
  :::
  :::flow-step{label="Output" icon="i-lucide-monitor"}
  Data goes back out: pixels, a saved file, a row in a database, a response. The
  screen says `SHORTLISTED`.
  :::
::

A university admissions system is that loop, several million times. So is a game,
a bank, and the browser you are reading this in.

## Completely literal

Here is the part that takes people a while. The machine has no judgement. If you
tell it to shortlist every applicant scoring *over* 80, an applicant on exactly
80 is rejected, and nothing anywhere will flag that as odd. Not the compiler, not
the operating system, not the screen. It is a perfectly correct execution of a
wrong instruction.

::compare{caption="The rule the registrar described, and the rule the machine was given."}
  :::compare-side{label="What the registrar said" verdict="neutral"}
  "Shortlist anyone who scored eighty or above."
  :::
  :::compare-side{label="What the machine was told" verdict="wrong"}
  `score > 80`. Everyone on exactly 80 is dropped. In a cohort of 4,200 that was
  61 people, and the first anyone heard about it was a phone call.
  :::
::

Every bug is that gap. Not the machine being unreliable, but the machine being
extremely reliable about the wrong thing.

## Unimaginably fast

The second half of the sentence. "Fast" is a word that has stopped meaning
anything, so here is a number you can feel: run this and watch how many simple
additions your machine gets through in a tenth of a second.

::runner{lang="javascript"}
```javascript
const start = Date.now()
let operations = 0

// Keep adding until a tenth of a second has gone by.
while (Date.now() - start < 100) {
  operations = operations + 1
}

console.log('Additions in 0.1 seconds:', operations.toLocaleString())
console.log('That is roughly', Math.round(operations / 100000), 'million per second')
```
::

Numbers in the tens of millions are normal, and this is a slow way of counting.
The real processor is doing several billion basic operations a second, and this
example is being throttled by the clock check on every pass.

Hold both facts at once, because together they explain the job:

::feature-list{columns="2"}
  :::feature{icon="i-lucide-gauge" title="Fast enough that scale is free"}
  Looping over 4,200 applicants costs nothing you can perceive. Do not
  optimise it. Beginners waste weeks here.
  :::
  :::feature{icon="i-lucide-crosshair" title="Literal enough that scale is fatal"}
  A rule that is wrong by one is wrong 4,200 times before you have finished
  reading the log. Speed is an amplifier, not a safety net.
  :::
::

## What confuses people here

The word "computer" now means the whole experience: the screen, the apps, the
account, the phone in your pocket. That bundle is not what we are talking about.

::warning{icon="i-lucide-alert-triangle"}
Almost everything you associate with a computer is software: the desktop, the
folders, the little bin you drag things to. Underneath is a machine doing
arithmetic on numbers. Every layer you meet in this course is somebody's clever
idea for hiding that fact, and the ones that leak are the ones you must
understand.
::

The other habit worth breaking now: "it decided to". It never decides. Something
told it to, and finding that something is the entire discipline of debugging.

::real-life{title="A wrong number that nobody questioned for a year" source="A registrar's office"}
A university's dashboard reported an average attendance of 93%. Nobody doubted
it, because the system was fast, modern, and had never crashed. It was averaging
only the rows where attendance had actually been marked, and the classes with the
worst attendance were the ones where nobody had bothered marking it. The machine
performed flawlessly. The number was nonsense for a year.
::

## What you can do now

You can describe, without hand-waving, what the box does: it takes data in, holds
it, does arithmetic and comparisons, and pushes data out. Several billion times
a second, and without a single opinion about whether any of it makes sense.

That is also the shape of the first program you write in the Java track: read an
applicant's marks, hold them, calculate a percentage, compare it to a cutoff,
print a decision.

## Your turn

Pick something you did on a computer today (sent a message, paid for something,
opened a photo) and write it out as the four boxes. Input, storage, processing,
output. Do it on paper, in a sentence each.

Processing: the bank compares the amount against my balance and the PIN against a stored value, and decides yes or no. Output: the terminal prints APPROVED, a row is written to my statement, and the shop's till updates.
