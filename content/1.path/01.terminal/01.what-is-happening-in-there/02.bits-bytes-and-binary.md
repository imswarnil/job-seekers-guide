It cannot hold the number 87. What it holds is a row of switches, each one on or
off, and a shared agreement about what a particular pattern of them means.

That agreement is all binary is. Not a mystical machine language — a counting
system with two digits instead of ten, plus a convention.

## Why this matters in a job

Three things you will hit in the first month make no sense without it. Why a
number silently becomes negative when it gets too big. Why a file is "2 MB" and
uploading it fails at a limit of 2,000,000. Why a colour is written `#f04e2e` and
a permission is written `755`.

None of that is trivia. Each one is a real afternoon lost if the underlying idea
is missing.

## Counting with two fingers

You count in tens because of your hands. Each position in a number is worth ten
times the one to its right: in `487` the 4 means four hundreds.

A machine has one finger per switch, and the switch is on or off. So each
position is worth **two** times the one to its right.

::memory{kind="array" caption="One byte — eight switches. The place value of each, and the pattern that means 87."}
---

      - { value: 1, state: "active" }

      - { value: 1, state: "active" }
---
::

Add up the positions that are on: 64 + 16 + 4 + 2 + 1 = 87. That is the whole
trick. There is nothing else to binary.

Two words, defined now because they are used everywhere afterwards:

::feature-list{columns="2"}
  :::feature{icon="i-lucide-toggle-right" title="A bit"}
  One switch. On or off, 1 or 0. The smallest thing a machine can hold. The word
  is short for *binary digit*.
  :::
  :::feature{icon="i-lucide-boxes" title="A byte"}
  Eight bits, grouped. Eight switches give 2 × 2 × 2 × 2 × 2 × 2 × 2 × 2 = 256
  different patterns, so one byte holds a whole number from 0 to 255.
  :::
::

## Watch the pattern

Run this. It prints the same applicant's score in three ways — as you write it,
as switches, and as the shorthand programmers use for switches.

::runner{lang="javascript"}
```javascript
const score = 87

console.log('Decimal, how you write it: ', score)
console.log('Binary, how it is stored:  ', score.toString(2).padStart(8, '0'))
console.log('Hexadecimal, the shorthand:', score.toString(16).toUpperCase())

// The place values that are switched on
const on = []
score.toString(2).padStart(8, '0').split('').forEach((bit, i) => {
  if (bit === '1') on.push(2 ** (7 - i))
})
console.log('Add these up:', on.join(' + '), '=', score)
```
::

Change `87` to a cutoff of `80`, or to `255`, or to `256`, and run it again.
Watch what happens at 256 — the pattern needs a ninth switch, which is exactly
where the next problem comes from.

## Hexadecimal, and why anyone bothers

`01010111` is eight characters that a human eye slides straight off. So there is
a shorthand: count in sixteens, using `0`–`9` and then `A`–`F` for ten to
fifteen. One hexadecimal digit is exactly four bits, so a byte is always exactly
two hex digits. That neatness is the entire reason it exists.

| You write | Hex | Binary | Where you have already seen this |
| --- | --- | --- | --- |
| 87 | `57` | `01010111` | An applicant's score in memory |
| 240 | `F0` | `11110000` | The red in `#f04e2e` — 240 parts red |
| 255 | `FF` | `11111111` | The largest value one byte can hold |

## Letters, and the same trick again

A machine holds numbers. A student's name is not a number. So there is a second
agreement: a table saying which number means which character. `A` is 65, `a` is
97, a space is 32. That table is Unicode, and the way those numbers get written
into bytes is usually UTF-8.

::runner{lang="javascript"}
```javascript
const name = 'Ananya'

for (const character of name) {
  console.log(character, '→', character.codePointAt(0), '→', character.codePointAt(0).toString(2).padStart(8, '0'))
}
```
::

Which means a text file, a photograph and a program are all the same thing on
disk: a long row of switches. The only difference is which agreement you read
them with. Open a photograph in a text editor and you get nonsense — not because
the file is broken, but because you applied the wrong agreement to it.

## What confuses people here

::warning{icon="i-lucide-alert-triangle"}
**A byte holds 0 to 255, not 0 to 256.** 256 different patterns, and one of them
is zero. Off-by-one at the boundary is the single most common mistake in this
whole subject, and it is the same mistake that will bite you in loops, arrays and
date ranges for the rest of your career.
::

The other one is quieter, and it costs real money:

::compare{caption="Two definitions of a megabyte, both in daily use."}
  :::compare-side{label="What the disk manufacturer means" verdict="neutral"}
  1 MB = 1,000,000 bytes. Counting in powers of ten, because that is how the box
  is marketed.
  :::
  :::compare-side{label="What the operating system means" verdict="neutral"}
  1 MB = 1,048,576 bytes — 2 to the power of 20. Counting in powers of two,
  because that is how memory is addressed.
  :::
::

This is why a "1 TB" drive shows up as 931 GB, and why an upload limit of "2 MB"
rejects a file your operating system swears is 2 MB. Nothing is broken. Two
people are using the same word for different numbers.

::real-life{title="The file upload that failed for one applicant in twenty" source="An admissions portal"}
Applicants uploaded scanned transcripts. The limit was set to 2,097,152 bytes on
the server and described as "2 MB" in the form. Phone cameras produce files
between 1.9 and 2.1 MB constantly, so roughly one applicant in twenty hit an
error that said nothing except "upload failed". The fix was one line. Finding it
took two days, because nobody involved thought a megabyte was ambiguous.
::

## What you can do now

You can read `01010111` and get 87 out of it, explain why one byte stops at 255,
say what hexadecimal is for, and answer the question "how does a computer store a
name?" without arm-waving: a number per character, and an agreed table.

Expected output from the first runnable block, so you can check yours:

```text
Decimal, how you write it:  87
Binary, how it is stored:   01010111
Hexadecimal, the shorthand: 57
Add these up: 64 + 16 + 4 + 2 + 1 = 87
```

## Check yourself

::accordion
---
items:
  - label: Why is a "1 TB" hard drive reported by your operating system as roughly 931 GB?
    icon: i-lucide-circle-help
    content: Because the two are counting in different bases. The manufacturer means 1,000,000,000,000 bytes — powers of ten. The operating system divides by 1024 at each step — powers of two — because that is how memory addressing works. 1,000,000,000,000 ÷ 1024³ ≈ 931. Nothing is missing and nothing is faulty.
  - label: "Interviewers ask this — how many values can one byte hold, and what is the largest?"
    icon: i-lucide-briefcase
    content: 256 values, and the largest is 255. Eight bits, two states each, 2⁸ = 256 patterns, and one of those patterns is zero. If the byte is signed — one bit spent on the sign — the range becomes −128 to 127, which is the follow-up question and the reason a counter can suddenly go negative.
