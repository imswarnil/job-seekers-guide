## Why this matters in a job

It doesn't, directly. This page exists for two other reasons.

The first is that you will meet these blocks in every subject from here on, and
a reader who knows that the dimmed lines in a code walkthrough are *deliberate*
spends their attention on the code rather than on the interface.

The second is that this platform is written in the open. If you ever want to fix
a lesson or write one, this is the whole vocabulary — there is no editor to
learn, and no code.

::real-life{title="The real reason this page exists" source="Every online course, ever"}
Somewhere around the fourth lesson of most online courses, a diagram appears
that the reader cannot interpret and does not ask about, because asking feels
like admitting something. They skim it. Two lessons later the thing it explained
is assumed knowledge. That is how people fall off a curriculum without ever
deciding to.
::

## Sequences

`::flow` is for anything that happens in an order.

::flow{numbered caption="What actually happens between a text file and a running process"}
  :::flow-step{label="You write text" icon="i-lucide-file-code"}
  `Admissions.java` is characters in a file. The machine has no idea what it means.
  :::
  :::flow-step{label="javac compiles" icon="i-lucide-cog"}
  Produces `Admissions.class` — bytecode, not machine code. This distinction is
  asked about constantly.
  :::
  :::flow-step{label="The JVM runs it" icon="i-lucide-play" highlight}
  Bytecode becomes machine instructions, at the last possible moment.
  :::
::

## Code, one step at a time

When a lesson would otherwise say "on line three...", it uses `::code-trace`
instead. The code stays where it is and the explanation walks down it.

::code-trace{caption="A bug that has shipped to production more times than anyone will admit"}
```java [Admissions.java]
int seats = 60;
int applicants = 4210;
double ratio = applicants / seats;
System.out.println("Applicants per seat: " + ratio);
```

  :::code-trace-step{lines="1-2" caption="Two integers. Nothing wrong yet, and nothing that looks like a bug."}
  :::
  :::code-trace-step{lines="3" caption="Here. Both operands are ints, so Java divides them as ints and throws the fraction away — before the double on the left ever sees the result. Widening to double happens after the damage."}
  :::
  :::code-trace-step{lines="4" caption="Prints 70.0. The right answer is 70.1666… The decimal point makes it look like the calculation was done in floating point, which is exactly why this one survives code review."}
  :::
::

## Short points, side by side

::feature-list{columns="2"}
  :::feature{icon="i-lucide-cpu" title="Its own memory"}
  One process cannot read another's address space. This is why a crash in your
  browser does not take the operating system with it.
  :::
  :::feature{icon="i-lucide-file" title="Its own file handles"}
  Closing a file in one process does not close it in another.
  :::
  :::feature{icon="i-lucide-git-fork" title="Its own threads"}
  All of them die when the process does.
  :::
  :::feature{icon="i-lucide-shield" title="Its own permissions"}
  Which is most of what "it works on my machine" turns out to mean.
  :::
::

## Prompts worth having

The job-search subjects teach AI as a tool rather than a shortcut, which means
handing you the actual words — and saying why they are those words.

::ai-prompt{title="Critique your resume bullets" model="Any"}
You are a hiring manager at a mid-size product company, reading resumes for a
junior backend role. Below are six bullets from mine.

For each one, tell me: what a reader learns about my impact, and what they
cannot tell. Do not rewrite them.

  #why
  It asks for a critique, not a rewrite. A rewrite hands you somebody else's
  words, which you then cannot defend in the interview. A critique tells you
  what yours were missing, and you fix them yourself.
::

## Code you can run

Press Run. Nothing downloads until you do, and a lesson without one of these
downloads nothing at all.

::runner{lang="javascript"}
```javascript
const applicants = 4210
const seats = 60

console.log('Integer division:', Math.trunc(applicants / seats))
console.log('Actual ratio:', applicants / seats)
```
::

SQL runs against a real SQLite, compiled to WebAssembly, in this tab:

::runner{lang="sql"}
```sql
CREATE TABLE applicants (name TEXT, branch TEXT, offers INTEGER);

INSERT INTO applicants VALUES
  ('Priya',  'mechanical', 0),
  ('Arun',   'cse',        2),
  ('Fatima', 'commerce',   1);

SELECT branch, COUNT(*) AS people, SUM(offers) AS offers
FROM applicants
GROUP BY branch
ORDER BY offers DESC;
```
::

Java is the one that leaves your browser, because compiling Java needs `javac`
and `javac` does not run in a tab. The lesson says so rather than pretending.

::runner{lang="java"}
```java
public class Main {
  public static void main(String[] args) {
    int seats = 60;
    int applicants = 4210;
    System.out.println("Integer division: " + (applicants / seats));
    System.out.println("Actual ratio: " + ((double) applicants / seats));
  }
}
```
::

## The interview question this answers

There isn't one. This is the only page on the platform that admits that up
front — which is itself the point. A lesson that cannot say where it shows up in
a job should say so, rather than inventing a reason.
