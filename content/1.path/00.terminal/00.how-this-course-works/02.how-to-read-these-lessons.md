These pages are not plain text. There are diagrams you step through, code you can
run in this tab, and solutions deliberately hidden until you have had a go. Two
minutes here saves you skimming past the best parts of every lesson after it.

## Why this matters in a job

It does not, directly — this is the only page in the whole course that will admit
that up front. It exists for two other reasons.

Somewhere around the fourth lesson of most online courses, a diagram appears that
the reader cannot interpret and does not ask about, because asking feels like
admitting something. They skim it. Two lessons later the thing it explained is
assumed knowledge. That is how people fall off a curriculum without ever
deciding to.

The second reason is that this whole course is markdown in folders. If a lesson
is wrong, it is a text file, and this page is the entire vocabulary needed to fix
it.

## Every lesson has the same eleven beats

Once you can feel the shape, you can read faster, and you can tell when you have
missed something.

::steps{level="3"}

### It opens by answering the last cliffhanger

One or two sentences, no preamble. If the first line of a lesson does not answer
the problem the previous one left you with, the lesson is broken.

### Why we are learning this

What breaks without it. What question you cannot answer yet. Never syntax before
the reason for it.

### The idea, analogy first

An everyday comparison, then the technical version. A variable is a labelled box.
A join is stitching two sheets together on a shared column. An index is the
tabbed edge of a phone book.

### A small example that runs

Short, and always about the university. Where it teaches something, the broken
version comes first — the real error text — then the fix.

### What confuses people here

The trap, named before you fall into it.

### How you would use this for real

One concrete situation inside a university that a registrar, a dean, a lecturer
or a student would actually have.

### What you get out of it

What you can now do, plus the actual result — the printed output, the rendered
page, the returned rows — so you can check your own run against mine.

### Your turn

The exercise. You attempt it before anything is revealed.

### Check yourself

Exactly two questions. One of them is the kind an interviewer actually asks.

### The cliffhanger

The problem this lesson has just created for you, left open. Always the last
thing on the page.

::

## Code, one step at a time

When a lesson would otherwise say "on line three…", it uses `::code-trace`
instead. The code stays where it is and the explanation walks down it. Press the
steps.

::code-trace{caption="A bug that has shipped to production more times than anyone will admit"}
```java [Admissions.java]
int seats = 60;
int applicants = 4210;
double ratio = applicants / seats;
System.out.println("Applicants per seat: " + ratio);
```

  :::code-trace-step{lines="1-2" caption="Two whole numbers. Nothing wrong yet, and nothing that looks like a bug."}
  :::
  :::code-trace-step{lines="3" caption="Here. Both sides are whole numbers, so Java divides them as whole numbers and throws the fraction away — before the decimal type on the left ever sees the result."}
  :::
  :::code-trace-step{lines="4" caption="Prints 70.0. The right answer is 70.166… The decimal point makes it look like the sum was done properly, which is exactly why this one survives code review."}
  :::
::

You will not understand that code yet. That is fine — it is the fourth lesson of
the Java track, and it is here as a demonstration of the component, not a test.

## Two ways of doing something

Used constantly, and in two flavours. **Broken and fixed** — one does not run.
**Wrong and right** — both run, and one of them silently returns the wrong
answer. The second is the more dangerous, and gets more space in this course than
you will expect.

::compare{caption="Both of these queries run without an error. One of them is lying to a dean."}
  :::compare-side{label="Silently wrong" verdict="wrong"}
  Counting students after joining to their exam results. Every student with four
  subjects is counted four times, and the department report is quietly four times
  too big.
  :::
  :::compare-side{label="Right" verdict="right"}
  Counting each student once, distinctly, and checking the row count against a
  number you already know.
  :::
::

## Where it shows up in a job

The most important block on the platform. The subjects are not secret. What is
missing everywhere else is somebody connecting them to the work.

::real-life{title="Why the deploy failed at 2am" source="A payments team"}
The service had a connection pool of ten and a thread pool of two hundred. Every
request past the tenth queued, the queue grew, and the health check timed out —
so the orchestrator killed a service that was working correctly and slowly. Four
people were awake for three hours over a number in a configuration file.
::

## Code you can run

Press Run. Nothing downloads until you do, and a lesson without one of these
downloads nothing at all.

::runner{lang="javascript"}
```javascript
const applicants = 4210
const seats = 60

console.log('Whole-number division:', Math.trunc(applicants / seats))
console.log('Actual ratio:', applicants / seats)
```
::

SQL runs against a real database engine compiled into this page:

::runner{lang="sql"}
```sql
CREATE TABLE applicants (name TEXT, program TEXT, score INTEGER);

INSERT INTO applicants VALUES
  ('Ananya Rao',   'B.Tech CSE', 87),
  ('Imran Sheikh', 'B.Tech CSE', 74),
  ('Meera Nair',   'B.Sc Maths', 91);

SELECT program, COUNT(*) AS applicants, ROUND(AVG(score), 1) AS avg_score
FROM applicants
GROUP BY program
ORDER BY avg_score DESC;
```
::

Java is the one that leaves your browser — compiling it needs a compiler, and a
compiler does not run in a tab. The component says so rather than pretending, and
the first run takes a few seconds.
