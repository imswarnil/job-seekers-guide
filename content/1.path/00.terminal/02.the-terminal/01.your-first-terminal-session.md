The faster way in is a text prompt where you type the name of what you want and
press enter. No hunting through menus, no waiting for a window, and — the part
that matters later — everything you type can be written down, repeated and
handed to another machine.

## Why this matters in a job

Because every instruction you will ever be given assumes it. "Clone the repo and
run it." "Check the logs on the server." "Install the dependencies." None of
those have a button. The graphical interface on your machine is a convenience
built over the top of a machine that has always been driven this way, and the
convenience stops existing the moment you connect to a server, which has no
screen at all.

::real-life{title="The first ten minutes of a first job" source="A junior developer, week one"}
Two people started the same week. Both had built things. One had spent a
fortnight in a terminal and had the project cloned, installed and running before
the stand-up. The other spent the morning asking where to click, and it was
noticed — not as ignorance, which nobody minds, but as a signal about how they had
learned. It took two months to shake.
::

## Open it

::tabs
  :::tabs-item{label="macOS" icon="i-lucide-command"}
  Press `Cmd + Space`, type `Terminal`, press enter. That is the built-in one and
  it is fine for this entire course.
  :::

  :::tabs-item{label="Linux" icon="i-simple-icons-linux"}
  `Ctrl + Alt + T` on most desktops, or search for "Terminal" in your
  applications. You are already on the operating system everything else in this
  course deploys to.
  :::

  :::tabs-item{label="Windows" icon="i-lucide-monitor"}
  Install **WSL** — the Windows Subsystem for Linux. Open PowerShell as
  administrator and run `wsl --install`, then restart. From then on, open
  "Ubuntu" or Windows Terminal. Do this rather than using PowerShell for the
  course: every command here, and nearly every instruction you will be given for
  the rest of your career, is written for a Unix-style shell.
  :::
::

You get a window with a line of text and a blinking block. That line is the
**prompt**, and it is telling you things.

```bash [Terminal]
swarnil@laptop ~ %
```

- `swarnil` — the user you are logged in as.
- `laptop` — the machine's name. This matters enormously later, when some of your
  prompts are on other people's machines.
- `~` — where you currently are. The squiggle is shorthand for your home folder.
- `%` — the end of the prompt. Yours may be `$` or `#`. Type after it.

::warning{icon="i-lucide-alert-triangle"}
A `#` at the end of the prompt usually means you are running as the
administrator, and every mistake is unrestricted. If you see one and did not
intend to, close the window. You will not need administrator rights for anything
in this chapter.
::

## Where am I?

The first command. Print working directory.

```bash [Terminal]
pwd
```

```text [Output]
/Users/swarnil
```

That string is a **path** — a route through the folder tree, with `/` between
each step. It starts at `/`, called the **root**: the top of everything on the
machine. There is no folder above it.

::flow{direction="vertical" numbered caption="Reading /Users/swarnil/projects/university-management-app from left to right."}
  :::flow-step{label="/" icon="i-lucide-hard-drive"}
  The root of the whole machine. Everything is somewhere below this.
  :::
  :::flow-step{label="Users" icon="i-lucide-users"}
  Where the people who use this machine have their folders. On Linux it is
  usually `home`.
  :::
  :::flow-step{label="swarnil" icon="i-lucide-house"}
  My home folder. This is what `~` is shorthand for.
  :::
  :::flow-step{label="projects/university-management-app" icon="i-lucide-folder-open" highlight}
  Where the university system will live for the rest of this course.
  :::
::

## What is here?

List.

```bash [Terminal]
ls
```

```text [Output]
Desktop    Documents    Downloads    Music    Pictures
```

Bare `ls` hides a lot. Commands take **flags** — extra instructions after a dash —
and two of them are worth having from your first day.

```bash [Terminal]
ls -l
```

```text [Output]
drwxr-xr-x   5 swarnil  staff   160 19 Aug 09:14 Desktop
drwxr-xr-x  12 swarnil  staff   384 18 Aug 22:03 Documents
-rw-r--r--   1 swarnil  staff  4210 19 Aug 11:47 applicants.csv
```

`-l` means long: permissions, owner, size in bytes, when it changed. The `d` at
the start of a line means directory; a `-` means an ordinary file. Those first
ten characters are the permissions from the last chapter, and they get a lesson
of their own shortly.

```bash [Terminal]
ls -la
```

`-a` means all, including hidden files — anything whose name starts with a dot.
There are more of these than you expect, and several of them matter: `.git`,
`.env`, `.gitignore`. **A file you cannot see is still a file you can commit by
accident.**

Flags combine: `ls -la` is the same as `ls -l -a`.

## Getting somewhere else

Change directory.

```bash [Terminal]
cd Documents
pwd
```

```text [Output]
/Users/swarnil/Documents
```

Four moves are worth memorising now, because you will type them thousands of
times:

| Command | What it does |
| --- | --- |
| `cd Documents` | Into a folder that is right here |
| `cd ..` | Up one level. `..` always means "the folder above this one" |
| `cd ~` | Straight home, from anywhere |
| `cd -` | Back to wherever you just were. Genuinely useful |

## Absolute and relative

Two ways to describe where something is, and mixing them up is the most common
early mistake.

::compare{caption="Getting to the same folder, two different ways."}
  :::compare-side{label="Absolute — from the root" verdict="neutral"}
  `cd /Users/swarnil/projects/university-management-app`

  Starts with `/`. Means the same thing typed from anywhere on the machine.
  Longer, and unambiguous.
  :::
  :::compare-side{label="Relative — from where you are" verdict="neutral"}
  `cd projects/university-management-app`

  No leading slash. Means "from here", so it only works if you are already in the
  right place. Shorter, and the cause of most "no such file or directory"
  errors.
  :::
::

Neither is better. Notice which one you are using — that is the skill.

## Two habits that make this bearable

**Tab completion.** Type the first few letters of a name and press `Tab`. The
shell finishes it. Press it twice and it lists the possibilities. This is not a
nicety: it prevents typos, and typos in a terminal are how the wrong file gets
deleted.

**Up arrow.** Cycles back through commands you have already run. Almost nobody
types a long command twice.

## When it goes wrong

You will see these three in your first ten minutes. They are sentences, not
walls.

```bash [Terminal]
cd Documnets
```

```text [Output]
cd: no such file or directory: Documnets
```

Spelling, or you are not where you think you are. Run `pwd` and `ls`, in that
order, every time. It becomes reflex.

```bash [Terminal]
cd applicants.csv
```

```text [Output]
cd: not a directory: applicants.csv
```

That is a file. You cannot go into a file.

```bash [Terminal]
lss
```

```text [Output]
zsh: command not found: lss
```

The shell looked for a program with that name and there isn't one. Either a
typo, or something you have not installed yet — and later in this course, that
second case will be the interesting one.

## What you can do now

You can open a terminal, tell where you are, see what is around you including
the hidden things, and move anywhere on the machine. That is genuinely the
majority of terminal use, and it took about ten minutes.

## Your turn

Do this now, in a real terminal. Reading it does nothing.

1. Open a terminal and run `pwd`. Write down what it says.
2. `ls -la` in your home folder. Count the hidden files. Find one you recognise.
3. Go into `Documents`, then back up, then home, using three different commands.
4. Make the path to your home folder in both forms — absolute and relative from
   `Documents` — and run `cd` with each.
5. Type `cd Doc` and press `Tab`. Then press up-arrow four times.

::accordion
---
items:
  - label: You run `cd projects` and get "no such file or directory", but you are certain the folder exists. What are the two things to check, in order?
    icon: i-lucide-circle-help
    content: First `pwd` — a relative path only works from the right place, and you are probably not in it. Then `ls -la` — the folder may exist with a different case or a leading dot. On macOS `Projects` and `projects` are the same to the filesystem but not to your eyes; on the Linux server it will run on, they are genuinely different folders.
  - label: "Interviewers ask this — what is the difference between an absolute and a relative path?"
    icon: i-lucide-briefcase
    content: An absolute path starts at the root, begins with `/`, and identifies the same location no matter where it is used. A relative path is resolved from the current working directory, so the same string means different things depending on where you are. It comes up in interviews via configuration and deployment — a relative path that works locally and breaks in production because the working directory differs is one of the most common deployment failures there is.
