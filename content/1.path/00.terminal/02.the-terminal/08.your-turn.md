Here it is. One file, nine questions, and the last one is a genuine report — the
kind a registrar would ask for and a beginner would write a program to produce.

## Why this matters in a job

Because this is the exact shape of a request you will get in your first month:
"can you tell me how many X there are, broken down by Y, from this file?" The
people who reach for a spreadsheet take an hour. The people who reach for a pipe
take a minute and can repeat it tomorrow.

## Set up the data

Run this exactly. It creates a larger applicants file inside the UniversityOS
folder you made earlier.

```bash [Terminal]
cd ~/projects/universityos
cat > applicants.csv <<'ROWS'
```

```text [Output]
      13 applicants.csv
```

Thirteen lines, twelve applicants. That difference is the first trap and it is
deliberate.

## The problems

Attempt each one before opening a solution. Where a problem says "without", the
restriction is the exercise.

::steps{level="3"}

### 1. The header, and only the header

Print the first line, and nothing else.

### 2. The last four applicants

Without opening an editor and without counting.

### 3. Everyone shortlisted

With line numbers, so you could go back to them.

### 4. Everyone who is not rejected

And then say honestly what is wrong with your answer.

### 5. How many applicants, exactly

Twelve, not thirteen. Prove it with a command rather than by knowing.

### 6. Every applicant from an agent, sorted by score

Highest first.

### 7. Save the shortlist

Write just the shortlisted rows to `notes/shortlist.csv`, then confirm it worked
without opening it.

### 8. How many applicants per programme

One line each, with a count, most popular first.

### 9. The report

Which source produces the most shortlisted applicants? One pipeline, one line.

::

## Solutions

Only after you have tried all nine.

::accordion
---
items:
  - label: 1 to 4
    icon: i-lucide-key
    content: "1. `head -n 1 applicants.csv`. 2. `tail -n 4 applicants.csv`. 3. `grep -n SHORTLISTED applicants.csv`. 4. `grep -v REJECTED applicants.csv` — and what is wrong with it is that the header row does not contain REJECTED either, so it is included in your results. `tail -n +2 applicants.csv | grep -v REJECTED` fixes it. Nearly everybody misses this the first time, and it is the same class of error as counting thirteen applicants."
  - label: 5 and 6
    icon: i-lucide-key
    content: "5. `tail -n +2 applicants.csv | wc -l` gives 12. `tail -n +2` means 'from line 2 onwards', which is worth remembering because header rows are everywhere. 6. `grep agent applicants.csv | sort -t, -k4 -rn` — `-t,` sets the separator, `-k4` sorts on the fourth field, `-rn` is reverse numeric. If you sorted without `-n` you got a string sort, where 9 comes after 80, and that is the second-most-common quiet bug in this chapter."
  - label: 7 and 8
    icon: i-lucide-key
    content: "7. `grep SHORTLISTED applicants.csv > notes/shortlist.csv` then `wc -l notes/shortlist.csv` — five rows, no header, which may or may not be what you wanted. 8. `tail -n +2 applicants.csv | cut -d, -f3 | sort | uniq -c | sort -rn`. Beginner version: pipes `cat` in at the front and forgets `tail`, so the header appears as a programme with a count of one. Experienced version: drops the `cat`, strips the header first, and checks the total adds up to twelve before believing any of it."
  - label: 9 — the report
    icon: i-lucide-key
    content: "`grep SHORTLISTED applicants.csv | cut -d, -f6 | sort | uniq -c | sort -rn` gives 3 website, 1 agent, 1 walk-in. Notice what you have just done: filtered rows, selected a column, grouped, counted and ordered. That is `SELECT source, COUNT(*) FROM applications WHERE status = 'SHORTLISTED' GROUP BY source ORDER BY 2 DESC`, which you will write for real in two tracks' time. Same five operations, same order, different notation — which is the reason this exercise is the last one in the chapter."
---
::

## One more, with a warning attached

Make a disposable copy of the project, look at it, and remove it. Run the `ls`
first, every time, and read what it prints before you type the next line.

```bash [Terminal]
cd ~/projects
cp -r universityos universityos-scratch
ls -la universityos-scratch
rm -r universityos-scratch
```

::caution{icon="i-lucide-skull"}
Notice there is no `-f` there, and nothing was lost by leaving it out. The habit
worth building is that `-f` is something you add when the machine has objected and
you have understood the objection — not something that lives in your fingers.
::
