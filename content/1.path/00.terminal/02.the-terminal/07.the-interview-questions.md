Here are the five. None of them are hard, and all of them are diagnostic: the
answers people give reveal in about ten seconds whether they have lived at a
prompt or revised for one.

## Why this matters in a job

Because these questions are not really about the commands. "How would you find
what is using port 3000?" is asking whether you have ever had a dev server refuse
to start and worked it out yourself. There is no way to fake the answer and no
need to, because you did the exercises.

## The five

::accordion
---
items:
  - label: How would you find every occurrence of a word across a whole project?
    icon: i-lucide-message-circle-question
    content: "`grep -rn \"cutoff\" .` — recursive from here, with line numbers. Then narrow it: `--include='*.java'` for one file type, or exclude the dependency folders, because the first run will be mostly noise. What they are checking — that your instinct on a new codebase is to search rather than to read from the top. Volunteering that you would exclude `node_modules` says you have done it for real."
  - label: A service will not start because the port is in use. What do you do?
    icon: i-lucide-message-circle-question
    content: "`lsof -i :3000` to find what is holding it, then `kill <pid>` — and `kill -9` only if that is ignored. Almost always it is a previous run of the same thing that never exited when the terminal window was closed. What they are checking — whether you can diagnose rather than restart the machine. This is the single most common first-week problem in the industry."
  - label: What is the difference between an absolute and a relative path?
    icon: i-lucide-message-circle-question
    content: "Absolute starts at `/` and means the same location from anywhere. Relative is resolved from the current working directory, so the same string points somewhere different depending on where you run it. What they are checking — deployment failures. A relative path that works locally and breaks in production, because the working directory is not what you assumed, is one of the classic ways a first deploy dies."
  - label: What does `chmod 755` mean?
    icon: i-lucide-message-circle-question
    content: "Owner read, write and execute; group and others read and execute. Three digits, one per audience, each the sum of read 4, write 2, execute 1. Standard for a script or a directory; 644 is standard for a data file. What they are checking — that you can read a permission string on sight, and that you know 777 is not a fix. On a directory, mention that execute means the right to enter it, not to run it."
  - label: How would you check whether a server is up, and whether the application on it is working?
    icon: i-lucide-message-circle-question
    content: "`ping host` answers reachability — is the machine there. `curl -i https://host/health` answers the different question of whether the application is responding, and what status code it returns. They are separate failures: a machine can be perfectly reachable with a crashed application on it. What they are checking — whether you distinguish the network from the service, because the first thing anybody asks in an incident is which of the two it is."
---
::

## The one that catches people

::compare{caption="'Have you used Linux?' — two honest answers."}
  :::compare-side{label="Overclaiming" verdict="wrong"}
  "Yes, I'm comfortable with Linux." Followed by a blank on `ps aux`, which
  retroactively puts a question mark over everything else you said.
  :::
  :::compare-side{label="Specific" verdict="right"}
  "I work in a terminal daily — navigating, grep, permissions, processes and ssh.
  I have not administered a server or written anything serious in bash." Precise,
  verifiable, and it makes the rest of your claims worth believing.
  :::
::

Say what you have done and stop there. An interviewer's job is calibration, and
the candidate who marks their own boundaries is easier to trust than the one who
does not have any.

## Your turn

Answer all five out loud, page closed, and for each one say the command as well
as the concept. If you can only say "I'd search for it" without producing
`grep -rn`, that is the gap this chapter's exercises were for.
