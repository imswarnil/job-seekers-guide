Producing a word cold is a different skill from recognising it. Here they all
are, in the order they arrived, each in one line you could say out loud.

## Why this matters in a job

Because nobody will define these for you. They arrive in a sentence, in a
meeting, at speed — and asking what one means feels expensive at exactly the
moment you are trying to look like you belong. Read this once now, and that
moment does not arrive.

## Numbers and storage

::field-group
  ::field{name="Bit" type="storage"}
  One switch. On or off, 1 or 0. Short for *binary digit*. The smallest thing a
  machine can hold.
  ::

  ::field{name="Byte" type="storage"}
  Eight bits, grouped. 256 possible patterns, so one byte holds a whole number
  from 0 to 255.
  ::

  ::field{name="Binary" type="storage"}
  Counting with two digits instead of ten. Each position is worth twice the one
  to its right.
  ::

  ::field{name="Hexadecimal (hex)" type="storage"}
  Counting in sixteens, using 0–9 then A–F. Shorthand for binary: one hex digit
  is exactly four bits, so a byte is always two hex digits.
  ::

  ::field{name="Unicode" type="storage"}
  The agreed table of which number means which character. `A` is 65. UTF-8 is the
  usual way those numbers get written into bytes.
  ::

  ::field{name="Overflow" type="storage"}
  What happens when a value is too large for the space holding it. Depending on
  the language, it wraps around to a wrong number or refuses outright.
  ::
::

## Logic

::field-group
  ::field{name="Logic gate" type="logic"}
  A tiny circuit taking one or two on/off inputs and producing one output. AND,
  OR, NOT and XOR are the ones worth knowing.
  ::

  ::field{name="AND" type="logic"}
  On only when both inputs are on. In a query: both conditions must hold.
  ::

  ::field{name="OR" type="logic"}
  On when either input is on. In a query: at least one condition must hold.
  ::

  ::field{name="XOR" type="logic"}
  On when the inputs differ. Either, but not both. It is the result digit of
  binary addition.
  ::

  ::field{name="Truth table" type="logic"}
  The complete list of inputs and outputs for a rule. The definition of a gate,
  written out.
  ::

  ::field{name="Precedence" type="logic"}
  Which operator binds first. AND binds tighter than OR, the way multiplication
  binds tighter than addition. Brackets override it.
  ::
::

## The machine

::field-group
  ::field{name="CPU / processor" type="hardware"}
  The part that executes instructions. Fetch, decode, execute, advance — a few
  billion times a second.
  ::

  ::field{name="Fetch–execute cycle" type="hardware"}
  The loop the processor never leaves: read the next instruction, work out what
  it means, do it, move on.
  ::

  ::field{name="Register" type="hardware"}
  A handful of values held inside the processor itself. The fastest storage
  there is.
  ::

  ::field{name="Cache" type="hardware"}
  A small, very fast memory on the processor, holding what is being used right
  now so it does not have to be fetched from RAM.
  ::

  ::field{name="RAM / main memory" type="hardware"}
  Working memory. Large, fast, reachable at any address in the same time — and it
  loses everything when the power goes.
  ::

  ::field{name="Address" type="hardware"}
  The number identifying one location in memory. How the machine finds a value
  without searching.
  ::

  ::field{name="Storage / disk" type="hardware"}
  An SSD or hard disk. Keeps its contents without power, holds far more than RAM,
  and is roughly a thousand times slower.
  ::

  ::field{name="Volatile" type="hardware"}
  Loses its contents when the power goes. RAM is volatile; storage is not. The
  word turns up in interviews more than you expect.
  ::
::

## The operating system

::field-group
  ::field{name="Operating system (OS)" type="software"}
  The program that starts first and never stops. Runs other programs, invents
  files, enforces permissions, and talks to the hardware on your behalf.
  ::

  ::field{name="Kernel" type="software"}
  The core of the operating system — the privileged part that actually touches
  hardware and checks every request.
  ::

  ::field{name="Program" type="software"}
  A file on disk. Instructions, inert, doing nothing.
  ::

  ::field{name="Process" type="software"}
  A running instance of a program, with its own memory, its own open files and
  its own identity number. One program, many processes.
  ::

  ::field{name="Scheduler" type="software"}
  The part of the operating system that decides which process gets the processor
  next, and for how long.
  ::

  ::field{name="System call" type="software"}
  Your program formally asking the kernel to do something it is not allowed to do
  itself — read a file, open a network connection, allocate memory.
  ::

  ::field{name="Permission" type="software"}
  A rule about who may read, change or run something. The reason "permission
  denied" is an answer rather than a fault.
  ::

  ::field{name="Kill" type="software"}
  Stopping a process. Ordinary, everyday, not dramatic. You will do it several
  times a day.
  ::
::

## How to use this

Do not memorise it. Cover the right-hand side and say each definition out loud
once — the ones you stumble on are the ones to reread. That takes six minutes and
it is worth more than rereading the whole chapter.
