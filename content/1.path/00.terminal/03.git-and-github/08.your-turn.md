Here is the mess, made on purpose, in a place where it costs nothing. By the end
of this page you will have destroyed a day of work and recovered it, which is the
only way I know to stop being afraid of that happening for real.

## Why this matters in a job

Because the first time you see `HEAD detached` or lose an afternoon to a bad
reset should not be on a Tuesday with a deadline. Do it now, on a repository that
does not matter, and it becomes a procedure rather than a crisis.

## What you are building

The real UniversityOS repository, in the state it will stay in until the Java
track starts filling it up. This is not a throwaway exercise — this is the folder
you will work in for the next year.

### Acceptance criteria

You are done when all of these are true. Check them off honestly.

::steps{level="4"}

#### A public repository called `universityos`

On GitHub, connected over SSH, with your local repository pushed to it.

#### A README that explains the project to a stranger

What it is, why it exists, the folder layout, and how to run the report script.
Under a hundred lines. Somebody who has never met you should understand it in
twenty seconds.

#### A `.gitignore` before anything else

At minimum `.env`, `.DS_Store`, `node_modules/`, `*.class`. Committed early
rather than added after something leaks.

#### At least eight commits, each with a real message

Present tense, one idea each, under about seventy characters. No "update", no
"changes", no "fix".

#### One feature built on a branch and merged

A branch, at least two commits on it, pushed, opened as a pull request, merged,
branch deleted.

#### One conflict, resolved deliberately

Caused on purpose, resolved into something better than either side, with a merge
message that says what you kept.

#### One recovery from `reflog`

A commit destroyed with `reset --hard` and brought back. Write down the two
commands you used.

#### A `notes/terminal-cheatsheet.md` in your own words

Not copied from the glossary page. The commands you actually reached for, in the
words you would use to explain them.

::

## The mess, step by step

Do these in order. Run `git status` between every one.

::steps{level="3"}

### Set the stage

Make sure `main` is clean, everything is committed, and everything is pushed. If
`git status` says anything other than "working tree clean" and "up to date with
origin/main", fix that first.

### Build something on a branch

Branch `add-department-report`. Write `sql/reports/by-department.sh` — a pipeline
over `applicants.csv` that counts applicants per programme. Commit it. Then
improve it — sort the output, strip the header row — and commit that separately.
Two commits, two messages.

### Open a pull request against yourself

Push the branch. On GitHub, open a pull request, then read your own diff as if
somebody else wrote it. Leave one comment on a line you would question. Merge it,
and delete the branch on both GitHub and your machine.

### Cause a conflict

Branch `tune-report` and change the last line of `by-department.sh`. Commit.
Switch to `main` and change the same line differently. Commit. Merge.

Read the markers before you touch anything. Resolve into the version that is
actually best — often a combination — and commit with a message saying what you
kept and why.

### Now break it

Commit something small first, so there is something to lose. Then:

```bash [Terminal]
git log --oneline
git reset --hard HEAD~2
git log --oneline
```

Two commits have vanished. Sit with that for a moment. This is the feeling you
are inoculating yourself against.

### Get it back

```bash [Terminal]
git reflog
```

Find the hash of the commit that was at the tip before your reset. Then:

```bash [Terminal]
git reset --hard <that-hash>
git log --oneline
```

Everything is back. Write down what worked and what did not — specifically,
whether anything you had *not* committed came back. It did not, and that is the
lesson.

### Leave it tidy

Push everything. Confirm on GitHub that the history reads properly from top to
bottom. Then write the cheat-sheet in `notes/`, commit it, and push.

::

::caution{icon="i-lucide-skull"}
Every destructive command on this page is aimed at `universityos`, which contains
nothing you cannot rebuild in twenty minutes. Do not practise `reset --hard` in a
folder holding anything real, and check `pwd` before each one. That check is the
habit; the commands are just the syllabus.
::

## If you get stuck

::accordion
---
items:
  - label: "\"HEAD detached at 3f7a1c9\" — what have I done?"
    icon: i-lucide-key
    content: "You have checked out a commit directly rather than a branch, so HEAD points at a commit with no branch label on it. Nothing is broken. Any commits you make here are not on a branch and are easy to lose. `git switch main` returns you to normal; if you made commits you want to keep first, `git switch -c rescue` turns them into a real branch."
  - label: My push is rejected and I do not know why
    icon: i-lucide-key
    content: "Read the message — it almost always says the remote has commits you do not. `git pull`, resolve anything that conflicts, push again. If you have rewritten your own local history with amend or reset and are certain nobody else has this branch, `git push --force-with-lease` is the safe form. Never plain `--force`, and never on `main` if anybody else could have pulled it."
  - label: The merge conflict is in a file I do not care about
    icon: i-lucide-key
    content: "You still have to resolve it — Git will not proceed with markers in the working tree. Open it, choose a side, delete all three marker lines, `git add` the file, and commit. `git merge --abort` is always available if you would rather start over, and there is no penalty for using it."
  - label: I committed something I should not have and it is already pushed
    icon: i-lucide-key
    content: "If it is a bad change, `git revert <hash>` and push — honest, safe, done. If it is a secret, rotate the credential first and treat the Git cleanup as the second problem. Deleting it in a new commit does not remove it from the history, and on a public repository it has already been read by a scanner."
---
::
