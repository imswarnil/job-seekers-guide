Twenty commands, and you will use six of them ninety per cent of the time. Here
they all are, with the six marked, so the tab you keep open is a short one.

## Why this matters in a job

Because Git vocabulary is used in conversation constantly — "rebase it", "did you
stage that", "it's on origin", "just revert" — and half of learning it is
learning the words rather than the tool. Nodding along without knowing is a slow
way to stay confused.

## The daily six

These are the ones that make up almost every day.

| Command | What it does |
| --- | --- |
| `git status` | Where you are and what has changed. Run it constantly |
| `git add <file>` | Stage a change for the next commit |
| `git commit -m "…"` | Record everything staged, with a message |
| `git push` | Send your commits to the remote |
| `git pull` | Bring down and merge commits from the remote |
| `git log --oneline` | Read the history, one line per commit |

## Everything else in this chapter

**Starting and connecting**

| Command | What it does |
| --- | --- |
| `git init` | Turn this folder into a repository |
| `git clone <url>` | Download a repository and its whole history |
| `git remote add origin <url>` | Point your repository at a remote |
| `git remote -v` | Show which remotes are configured |
| `git config --global user.name "…"` | The name stamped on your commits |

**Looking at things**

| Command | What it does |
| --- | --- |
| `git diff` | Changes you have made but not staged |
| `git diff --staged` | Changes staged and about to be committed |
| `git log --oneline --graph` | The history with branches drawn |
| `git show <hash>` | Everything one commit changed |
| `git blame <file>` | Who last changed each line, and in which commit |

**Branching**

| Command | What it does |
| --- | --- |
| `git switch -c <name>` | Create a branch and move to it |
| `git switch <name>` | Move to an existing branch |
| `git branch` | List branches; the asterisk is where you are |
| `git merge <name>` | Bring that branch's commits into this one |
| `git merge --abort` | Back out of a merge that went badly |
| `git branch -d <name>` | Delete a branch that has been merged |

**Undoing**

| Command | What it does |
| --- | --- |
| `git restore <file>` | Discard uncommitted edits. **Destroys work** |
| `git restore --staged <file>` | Unstage, keeping the edits. Safe |
| `git commit --amend` | Rewrite the last commit. Only before pushing |
| `git revert <hash>` | A new commit undoing an old one. Safe on shared branches |
| `git reset --soft <hash>` | Move the branch back, keep changes staged |
| `git reset --hard <hash>` | Move back and **destroy everything uncommitted** |
| `git stash` / `git stash pop` | Park uncommitted work, then bring it back |
| `git reflog` | Everywhere HEAD has been. How you recover "lost" commits |

## The words

::field-group
  ::field{name="Repository (repo)" type="git"}
  A project folder with its whole history, stored in the hidden `.git` directory
  inside it.
  ::

  ::field{name="Commit" type="git"}
  A snapshot of the tracked files at one moment, with an author, a timestamp, a
  message and a pointer to the commit before it.
  ::

  ::field{name="Hash" type="git"}
  The long identifier of a commit — `3f7a1c9…`. Usually written as the first
  seven characters.
  ::

  ::field{name="HEAD" type="git"}
  Where you are standing right now. Usually the tip of the current branch.
  `HEAD~1` is one commit before it.
  ::

  ::field{name="Staging area (index)" type="git"}
  The list of changes chosen for the next commit. The middle step that lets one
  commit be one idea.
  ::

  ::field{name="Working directory" type="git"}
  The files as they are on disk at this moment, edits and all.
  ::

  ::field{name="Branch" type="git"}
  A movable label pointing at a commit, so several lines of work can grow from
  the same history.
  ::

  ::field{name="main" type="git"}
  The conventional name for the primary branch. Older projects call it `master`.
  ::

  ::field{name="Remote" type="git"}
  A copy of the repository somewhere else. `origin` is the conventional nickname
  for the one you cloned from.
  ::

  ::field{name="Push / pull / fetch" type="git"}
  Push sends your commits up. Fetch brings theirs down without touching your
  branch. Pull is fetch plus merge.
  ::

  ::field{name="Merge" type="git"}
  Bringing one branch's commits into another. Produces a merge commit when both
  lines have moved.
  ::

  ::field{name="Merge conflict" type="git"}
  Both branches changed the same lines, so Git stops and asks. A text file with
  three markers in it, not a disaster.
  ::

  ::field{name="Pull request (PR)" type="git"}
  GitHub's wrapper around a merge: the diff, line-by-line comments, approval,
  then merge. Where most team discussion happens.
  ::

  ::field{name="Rebase" type="git"}
  Replaying your commits on top of another branch to get a straight history
  instead of a merge commit. Not taught here; you will meet the word, and the
  rule is the same — never on shared history.
  ::

  ::field{name="Fork" type="git"}
  Your own copy of somebody else's repository on GitHub, so you can change it and
  propose the change back.
  ::

  ::field{name="`.gitignore`" type="git"}
  A file listing what Git should never track: secrets, dependencies, build
  output, machine-specific files.
  ::

  ::field{name="Force push" type="git"}
  Overwriting the remote branch with your version, deleting commits it had.
  `--force-with-lease` is the safer form. Never on a shared branch.
  ::
::
