## Why this matters in a job

In your first week somebody will say "it works on my machine". In your first
month somebody will ask "is that a hardware problem or a software problem?" Both
sentences assume you have a clear line in your head between the machine and the
instructions running on it. Most people never draw that line explicitly, and
then spend years slightly confused about where their code actually lives.

## The definition

**Software is a set of instructions that tells hardware what to do.** That is
the whole thing. Everything else in this curriculum is a consequence.

A computer is a machine that can do a small number of extremely boring things —
add two numbers, compare two numbers, move a number from here to there, jump to
a different instruction — at a rate of billions per second. It has no ideas. The
entire industry exists because arranging those boring operations in the right
order produces things that look nothing like arithmetic: a video call, a
payments system, a university admissions portal.

## The layers

You will hear people talk about "the stack". This is the honest version of it,
bottom to top:

| Layer | What it is | Example |
| --- | --- | --- |
| Hardware | Physical circuits that execute instructions | The CPU in the laptop you are reading this on |
| Firmware | Instructions burned into a device | The BIOS that starts before the OS |
| Operating system | The program that manages every other program | Linux, Windows, Android |
| Runtime / libraries | Reusable machinery your program stands on | The Java Virtual Machine |
| Application | The thing a person actually uses | The admissions portal |

::tip{icon="i-lucide-lightbulb"}
Every layer is software except the first one. An operating system is not a
special magical category — it is a program, written by people, that happens to
have the job of starting and supervising other programs. You will study it
properly in Operating Systems.
::

## A concrete example

Here is a complete program. It is software.

```java [Admissions.java]
public class Admissions {
    public static void main(String[] args) {
        int applicants = 1420;
        int seats = 120;
        System.out.println("Applicants per seat: " + applicants / seats);
    }
}
```

That is instructions on the left, hardware doing arithmetic on the right. There
is no third thing.

## The three kinds you will be paid to write

1. **Systems software** — operating systems, databases, compilers, browsers. Software whose users are other programs. Fewer jobs, deep specialisation, usually needs several years first.
2. **Application software** — the portal, the app, the internal dashboard. Software whose users are people. This is where the overwhelming majority of entry-level jobs are, and where this curriculum takes you.
3. **Infrastructure and tooling** — the pipelines, deployment systems and monitoring that get the other two into the world. Increasingly a first job in its own right.

::warning{icon="i-lucide-scissors"}
You do not need to choose between these now. You need to know they exist, so
that when a job description says "platform engineer" you know which one it is
talking about.
::

## The interview question this answers

**"What happens when you run a program?"**

Your two-sentence answer, for now: the operating system loads the program's
instructions into memory, and the CPU executes them one at a time, extremely
fast. The next lesson makes that answer good enough to defend.
