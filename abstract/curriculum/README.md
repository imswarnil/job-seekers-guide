## The semester model

Foundations are chunked into semesters so eleven subjects don't arrive as one
undifferentiated wall:

| Semester | Theme | Subjects |
|---|---|---|
| **0** | Orientation | How the IT Industry Works |
| **1** | The Machine | Operating Systems · Computer Networks |
| **2** | The Data | DBMS · SQL in practice |
| **3** | The Code | OOP · Data Structures & Algorithms |
| **4** | The Craft | Software Engineering · Web Technologies |
| **5** | The Scale | System Design · AI overview · Theory of Computation |
| **∥** | Running throughout | English & Communication · your language |

## What is deliberately excluded

| Excluded | Why |
|---|---|
| **Mathematics** (calculus, discrete, engineering maths) | Not required for a software job. Saying this plainly unblocks a large number of capable people who ruled themselves out. |
| Aptitude/reasoning drills | Some companies test it; it's a short, separate prep, not a subject |
| Microprocessors, digital electronics | Real CS subjects; not load-bearing for software employment |
| Certification farming | Projects prove more than certificates, at a fraction of the cost |
| "Learn 12 frameworks" | One language, one track, done properly |

## Teaching principles for every lesson

1. **Why before what** — open with where this shows up in a real job
2. **Show, then explain** — a running example before the definition
3. **Name what to skip** — explicitly mark the parts that don't matter yet
4. **End with a check** — a quiz, an exercise, or a thing to build
5. **Interview link** — how this subject actually gets asked

## Content strategy

We curate aggressively. A lesson may be:

- **Original** — written here, because nothing good exists
- **Curated** — the best free video/article on the internet, with our framing,
  our ordering, and our "read this, skip that" notes
- **Practice** — an exercise, quiz, or project spec

Curation is not laziness — it is the product. See
[../04-vision-and-principles.md](../04-vision-and-principles.md), principle 1.
