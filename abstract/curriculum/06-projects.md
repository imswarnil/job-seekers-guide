# Module 6 — Projects 1 → 4

**Duration:** 6 weeks · **The module that produces your evidence.**

> Certificates say you attended. Projects say you can do it. Every interview
> you'll have will spend more time on your projects than on anything else on
> your resume — so build four you can defend.

## The escalation

| # | Format | Support | Purpose |
|---|---|---|---|
| **1** | Follow along, step by step | Full walkthrough | Confidence — the first thing that *works* |
| **2** | Same project, new features | Spec + hints | Understanding — change it, break it, fix it |
| **3** | Written spec, you build it | Requirements only | Independence — the resume project |
| **4** | Your own idea | Review + feedback | Ownership — the one you'll actually talk about |

## Web track (default)

### Project 1 — Personal portfolio site
Static, responsive, deployed to a real domain. Teaches HTML/CSS/JS, Git, and
deployment. **Doubles as an asset you'll link from your resume.**

### Project 2 — Blog / CMS with authentication
Full CRUD, login, roles, a database. The shape of most working software. Then:
add search, add pagination, add image uploads — three features you implement
without a walkthrough.

### Project 3 — Job Application Tracker *(spec only)*
Given a written requirements document, build it: track applications, statuses,
companies, interview dates, notes, reminders. Real schema decisions, real API
design, real UI decisions.

> Deliberately chosen because you will **actually use it** during Module 7. A
> project you use is a project you can talk about with conviction.

### Project 4 — Your own idea
Scoped with a template, reviewed at the design stage, built independently,
reviewed at the end. Must be deployed, must be on GitHub, must solve a problem
you personally have.

## Rules that make projects count

1. **Deployed or it doesn't exist.** A localhost demo cannot be shown in an
   interview.
2. **On GitHub, with real commit history.** Interviewers look. A single
   "initial commit" of 4,000 lines is a red flag.
3. **A README that a stranger can follow** — what it does, why you built it, how
   to run it, screenshots.
4. **You can explain every line.** Not memorised — understood. If you can't
   explain it, you didn't build it.
5. **Solve a problem you actually have.** For project 4 especially. Conviction
   is audible.

## What not to build

- The same to-do app that 40,000 other applicants submitted
- A tutorial clone with the tutorial's variable names still in it
- Something with 30 features and none finished
- Something you can't deploy because it needs a GPU

## The project → resume pipeline

Every completed project generates a **resume block** — one line of what it is,
three bullets of what you did and what it demonstrates, the live link, and the
repo — carried directly into Module 7.
