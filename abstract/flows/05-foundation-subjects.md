# Step 5 — Choose your foundation subjects

## The screen

> ### The subjects that actually matter
> These are the same subjects taught in the best engineering colleges in the
> country — including the IITs. The syllabus was never the secret. Being taught
> them properly is.
>
> **Select all** is recommended. You can pace them across semesters.

### Locked, always included

> **🔒 Module 0 — What is Software / How the IT Industry Works**
> Included for everyone, always, first. Before you can choose what to become,
> you need to see what exists. There are N number of tools and roles out there;
> the foundation is what lets you choose between them instead of guessing.
> *Cannot be deselected.*

### Selectable subjects

| Subject | Why it matters in a job |
|---|---|
| **Operating Systems** | Processes, threads, memory, deadlocks — asked in almost every interview, and the reason your server falls over |
| **DBMS** | Every application has data. Schemas, joins, indexes, transactions, normalisation |
| **Computer Networks** | HTTP, TCP/IP, DNS, ports, latency. You cannot debug a web app without this |
| **Object-Oriented Programming** | How real codebases are structured. Taught alongside your chosen language |
| **Data Structures & Algorithms** | The interview round everyone fears, and genuine problem-solving skill |
| **Theory of Computation / Compiler Design** | Lighter, but explains *how* your code becomes something that runs |
| **Software Engineering** | SDLC, Agile, sprints, version control, testing, code review — how work actually happens |
| **Web Technologies** | HTTP, HTML/CSS/JS, client–server, APIs, REST. The base under almost every job |
| **System Design** | How real systems scale. Decides your salary band more than any other subject |
| **Artificial Intelligence** | What AI/ML actually is, what's hype, and how it's used in real products |
| **English / Communication Skills** | You will be rejected for this. Runs alongside everything else, never as a gate |

### Controls on the screen

- **[ Select all — recommended ]** — the default, one tap
- **[ Just the essentials ]** — OS, DBMS, Networks, OOP, DSA, Web
- Individual checkboxes for full control
- Each subject expands to show: *why it matters*, *how long it takes*, *which
  roles lean on it hardest*

## Sidebar copy

> **What is NOT on this list, and why.**
>
> **Mathematics.** Not required. Not calculus, not discrete maths, not
> engineering maths. You can have an excellent, well-paid career in software
> without any of it. If you go deep into ML research or graphics later, you'll
> pick up what you need then. For a job in software — you do not need it, and
> being bad at maths does not disqualify you from anything here.
>
> That single sentence is the reason a lot of capable people never tried.

> **Why these and not others?** Because these are the ones that come up in
> interviews, in real work, and in every conversation you'll have with a senior
> engineer. Not because a university put them on a marksheet.

## The semester model

Selected subjects are laid out as a **semester plan** rather than a flat list —
because a flat list of eleven subjects is paralysing, and because the framing is
familiar to anyone who has been to college.

```
Semester 0  ·  Orientation      How IT Works  (2 weeks, everyone)
Semester 1  ·  The Machine      OS · Computer Networks
Semester 2  ·  The Data         DBMS · SQL in practice
Semester 3  ·  The Code         OOP · DSA · (your language, in parallel)
Semester 4  ·  The Craft        Software Engineering · Web Technologies
Semester 5  ·  The Scale        System Design · AI overview · ToC/Compilers
Running throughout ·            English / Communication
```

The learner picks a pace — **relaxed / regular / intense** — which sets the
week-count per semester and the estimated finish date shown on the dashboard.
